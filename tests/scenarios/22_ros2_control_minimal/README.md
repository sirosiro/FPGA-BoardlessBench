## 1. 背景と狙い（Why F-BB × ROS 2）

ROS 2（Robot Operating System 2）エコシステムにおいて、Gazebo などの物理シミュレータと `ros2_control` は、ハードウェアを抽象化することで上位の自律走行（Nav2）やアーム制御（MoveIt）アルゴリズムを爆速で開発できる業界標準です。

しかし、実機ロボット開発（Zynq, Kria SOM, i.MX 等への組込み）の現場では、**「シミュレータ上で完璧に動いたコードを実機に投入した瞬間、モータが逆回転して壁に激突したり、緊急停止ボタンを押しても止まらず暴走する」** という致命的トラブルが後を絶ちません。

### ROS 2 開発スタイルの構造的「死角」
Gazebo やモックドライバはハードウェアを「C++ の関数引数レベル」で抽象化・バイパスして数値を直接代入するため、以下の**低層レイヤーが一切検証されないまま実機へ投入されてしまう**のが根本原因です：

1. **Linux UIO デバイスドライバ (`/dev/uio0`) のオープン・mmap 処理**
2. **1kHz タイマ割り込み（IRQ）の待機同期とスレッド起床ジッター**
3. **MMIO レジスタのエンディアン、アライメント、Read-Only 領域の保護**
4. **32bit エンコーダカウンタのオーバーフロー／ラップアラウンド時の速度計算**
5. **ハードウェアレベルでの E-STOP（非常停止）即時遮断シーケンス**

F-BB は Gazebo と競合するのではなく、**ROS 2 の洗練された開発スタイルを 1ミリも損なうことなく、ROS 2 単体ではカバーできない「足元の Linux ドライバ・FPGA レジスタ境界」を実機レスで 100% 補完** します。

## 2. 実機透過性 100% (Hardware Transparency)

F-BB の核心哲学である **「実機透過性 100%」** を徹底するため、シミュレータ固有の共有メモリ直叩き（`shm_open`）や `#ifdef SIMULATION` 分岐は**コード内に 1 行も存在しません**。

本シナリオで実装されている `UioRobotHardware`（C++ プラグイン）は、実機（Kria KR260 や Zynq-7000）の Linux カーネル（`uio_pdrv_genirq`）上でも、**1 行の変更もなくそのままコンパイル・実行できる完全な実機製品コード** です。

```text
[ ROS 2 / ros2_control Controller Manager ]
                     │ read() / write() (1kHz 制御ループ)
                     ▼
[ uio_robot_hardware.cpp (SystemInterface 実装) ]
  ★ 実機と F-BB で完全共通コード (#ifdef SIMULATION 排除)
                     │ open("/dev/uio0"), mmap(), read(uio_fd)
                     ▼
[ Linux システムコール境界 (C-Shim による透過捕捉) ]
  ・プロトコル・アサーション (RO レジスタ誤書込検知)
  ・カオス障害注入 (タイマ割込欠落、遅延エミュレーション)
                     │ ゼロコピー MMIO & eventfd
                     ▼
[ Verilator RTL (vfpga_top.v: 1kHz 割込 / PWM / 直交エンコーダ) ]
```

本シナリオは、F-BB の実績ある既存資産を直接組み合わせて構築されています：

| 継承元シナリオ | 継承したコア資産 | 本シナリオでの役割 |
| :--- | :--- | :--- |

## 4. 6大合否判定基準（現場の死角を突く自動テスト仕様）

本シナリオのテストリグ（`main.cpp`）は、単なる通信確認ではなく、組込み現場で致命的となる以下の 6 つの基準を厳格にアサーション検証します：

| 判定基準 | 合否基準 (Pass Criteria) | 現場で防止する事故・トラブル |
| :--- | :--- | :--- |
| **① 1kHz リアルタイムジッター** | 1kHz (1000µs) ループの起床ジッターが **最大 500µs 未満（シミュレーション環境）** に収まること。 | 制御周期の乱れによる PID ゲイン破綻、カルマンフィルタの発散。 |
| **② 左右輪対称性＆回転方向** | 左右輪に目標値（+400, -400）を与えた際、エンコーダが**それぞれ正負方向に加算・減算**され、目標 0 で完全にカウントが静止すること。 | モータ配線・エンコーダ A/B 相の逆接続による、電源投入直後の超高速スピン暴走。 |
| **③ E-STOP ハードウェア即時遮断** | `CONTROL[1]`（ESTOP）をアサートした瞬間、**次クロック（1 周期以内）で PWM 出力が強制 0%** に遮断され、`STATUS[0]`（FAULT）がアサートされること。 | アプリケーションがビジーループやハングを起こした際、非常停止が効かない重大事故。 |
| **④ プロトコルアサーション検知** | Read-Only レジスタ（`STATUS`）への誤書き込みをハードウェアが無視し、C-Shim が**プロトコル違反警告（ADR #010）**を発行すること。 | 不正メモリアクセスやドライバ側のポインタ取り違えバグの早期発見。 |
| **⑤ 32bit ラップアラウンド耐性** | エンコーダ値が `0x7FFFFFFF` ➔ `0x80000000` の符号境界を跨いだ際、速度計算が**差分（$\Delta \theta$）により正しく処理され、巨大な速度スパイクが発生しないこと**。 | 長時間連続走行時にオドメトリが突然数千km先へテレポートし、自律走行が暴走する定番バグの根絶。 |
| **⑥ 1kHz サイクルカウンタ同期** | ハードウェアのフリーランニングカウンタ（`CYCLE_CNT`）が 1kHz 周期ごとに確実にインクリメントされていること。 | タイマ回路のクロック分周ミスや、割り込みハンドラの多重トリガ防止。 |

## 5. テストの実施方法（動かしてみよう！）

本シナリオは、CI およびローカル環境で 6 大合否判定基準を高速に自動検証する**バッチ型回帰テスト**です（※対話型 Web ダッシュボードの対象外です）。

### ① シナリオ単体での自動テスト実行 (CLI)
ターミナルで以下のコマンドを実行すると、シミュレーションエンジンが自動ビルドされ、6大合否判定基準のアサーション検証が一括実行されます：

```bash
# シナリオディレクトリ内から実行する場合
cd tests/scenarios/22_ros2_control_minimal
./run.sh

# またはリポジトリルートから実行する場合
./tests/scenario_runner.sh tests/scenarios/22_ros2_control_minimal
```

実行後、ターミナル上に全 6 項目の `[ PASS ]` と `>>> ALL 6 CRITERIA PASSED! Scenario 22 Verification SUCCESS. <<<` が出力されます。

### ② 全体回帰テストでの一括実行
F-BB の全 35 シナリオの一括回帰テストに含まれており、以下のコマンドでまとめて検証可能です：

```bash
./tests/regression_test.py
```

## 6. UIO レジスタマップ仕様書 (`vfpga_robot_uio@40000000`)

実機標準の Device Tree（`config.dts`）から自動生成される UIO レジスタマップです：

| オフセット | レジスタ名 | 属性 | ビット幅 | 詳細仕様 |
| :---: | :--- | :---: | :---: | :--- |
| `0x00` | **`STATUS`** | RO | 32 | モータドライバステータス<br>・**bit[0]**: FAULT / ESTOP アクティブ<br>・**bit[1]**: ENABLED（走行可能状態）<br>・**bit[2]**: IRQ_PENDING（1kHz タイマ割込発生中） |
| `0x04` | **`LEFT_ENCODER`** | RO | 32 (signed) | 左輪直交エンコーダ累積パルス（32bit 符号付きカウンタ） |
| `0x08` | **`RIGHT_ENCODER`**| RO | 32 (signed) | 右輪直交エンコーダ累積パルス（32bit 符号付きカウンタ） |
| `0x0C` | **`INT_ACK`** | WO | 32 | 1kHz タイマ割込クリアレジスタ<br>・**bit[0]** に 1 を書き込むと `STATUS[2]` および `irq_out` がクリア |
| `0x10` | **`CONTROL`** | RW | 32 | 制御レジスタ<br>・**bit[0]**: RUN（タイマ・モータ有効化）<br>・**bit[1]**: ESTOP（ハードウェア非常停止）<br>・**bit[2]**: RESET（エンコーダカウンタのリセット）<br>・**bit[3]**: TEST_LOAD（テスト用エンコーダ値プリロード許可） |
| `0x14` | **`LEFT_PWM`** | RW | 32 (signed) | 左輪目標 PWM デューティ比（-1000 〜 +1000） |
| `0x18` | **`RIGHT_PWM`** | RW | 32 (signed) | 右輪目標 PWM デューティ比（-1000 〜 +1000） |
| `0x1C` | **`CYCLE_CNT`** | RO | 32 | 1kHz 周期フリーランニングサイクルカウンタ |

## 7. オンデマンド依存管理とクリーンアップ

### ゼロ・ヘビーインストール設計
- ホスト環境やコンテナ内に実機 ROS 2（Humble 等）がインストールされている場合は自動検出し、システムの `hardware_interface` を使用します。
- ROS 2 が存在しない標準 F-BB 環境では、シナリオ直下の [`include/hardware_interface/hardware_interface.hpp`](include/hardware_interface/hardware_interface.hpp) に用意された軽量互換ヘッダーを用いて **外部ダウンロードなし・数秒** でコンパイルが完了します。
- `./tests/run_tests.sh --cleanall` を実行することで、生成されたバイナリ等は完全に消去され、リポジトリの純粋なコード行数（Pure LOC）を常に保ちます。

## 8. Web ダッシュボード連携（将来構想ロードマップ）

直前に導入された **DPPA（Dashboard Pane Plugin Architecture）** により、今後ロボティクス実践プロジェクト（`P02_robot_amr_ros2`）等において、Web ダッシュボード（ポート 8080）へ「**ROS 2 Actuator Cockpit**」ペインをプラグイン登録・拡張可能です。

- **左右輪追従波形**: 目標 PWM 値に対するエンコーダ実測速度の追従グラフ（Recharts）をリアルタイム描画。
- **1kHz ジッターメーター**: 制御周期の平均・最大ジッターをリアルタイム表示。
- **マルチモニタ Pop-out**: タブ右上の切り離しボタンをクリックすることで、サブディスプレイへ全画面表示して常時監視可能。
