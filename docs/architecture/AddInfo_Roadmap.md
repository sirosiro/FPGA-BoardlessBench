# FPGA-BoardlessBench (F-BB) ロードマップ

本ドキュメントは、FPGA-BoardlessBench (F-BB) の今後の進化に向けた開発ロードマップです。  
すでに実現・統合された機能（GPIO, UART, I2C, SPI, AXI CDMA, SocketCAN, SDカード, PPA/DPPA プラグイン, Linux + RTOS/ベアメタル AMP 等）については [README.md](../../README.md) および [AddInfo_history.md](./AddInfo_history.md) を参照してください。

## 1. Zynq PS ペリフェラル対応状況と未実装テーマ

主要な Zynq PS 内蔵ペリフェラルの実装ステータス、および直近〜中期で取り組む未実装機能の方向性です。

| ペリフェラル | Zynq 仕様 | ステータス | エミュレーションの方向性・残課題 | 優先度 |
| :--- | :--- | :--- | :--- | :--- |
| **GPIO (MIO/EMIO)** | 最大118本 | **対応済** | 118ch双方向、Web UI トグルスイッチ/LED連携 | - |
| **UART** | 2ポート | **対応済** | PTYリダイレクト、マルチポート同時監視、TCPブリッジ | - |
| **I2C** | 2ポート | **対応済** | ioctl横取り・UNIXソケット中継（AT24C02C, SSD1306等） | - |
| **SPI** | 2ポート | **対応済** | マルチスレーブ（Flash/ADC）、PL物理ピン同期ブリッジ | - |
| **SD/SDIO** | 2ポート | **対応済** | システムコールフックによるローカルディレクトリ透過マウント | - |
| **CDMA / DMA** | 1チャネル (AXI CDMA) | **対応済** | C-Shim Writeフックによる即時 memcpy、アライメント検証 | - |
| **CAN** | 2ポート | **対応済** | Linux標準 SocketCAN (AF_CAN) 100% 透過エミュレーション | - |
| **QSPI Flash** | 1ポート | **未対応** | `mmap` による仮想 ROM イメージの高速読み出しと実行（XIP: Execute-in-Place） | 高 |
| **Ethernet (GEM)** | 2ポート | **未対応** | ホスト Linux の TAP/TUN デバイスと直結し、仮想 FPGA を LAN 内の独立した IP ノードとして透過通信 | 中 |
| **USB 2.0 (OTG)** | 2ポート | **未対応** | 仮想 USB デバイススタック（USB/IP または V4L2 仮想カメラ・マスストレージ連携） | 低 |
| **WDT (Watchdog)** | 3個 | **未対応** | 周期キック監視とタイムアウト時の仮想リセット・アラート発報 | 低 |
| **TTC (Triple Timer)** | 2個 | **未対応** | ナノ秒精度のクロック同期タイマーイベントおよび割り込み発火 | 低 |

## 2. 近〜中期ペリフェラル仮想化の設計方針

### QSPI Flash / XIP (Execute-in-Place) エミュレーション
* **目的**: ブートローダー（U-Boot / FSBL）やベアメタルファームウェアが QSPI Flash 上のコードを直接実行する XIP 動作をシミュレート。
* **アーキテクチャ**: ホスト上のバイナリファイルをメモリマップ（`mmap`）し、C-Shim 経由で Flash コントローラのリード要求に対してゼロコピーでデータを供給。

### Ethernet (GEM) TAP/TUN ネットワークブリッジ
* **目的**: 仮想 FPGA 上で動作する組み込み Linux や lwIP スタックに対し、ホスト PC や外部 LAN から実際の IP アドレス（HTTP, SSH, ROS 2 トピックなど）で直接アクセス可能にする。
* **アーキテクチャ**: Linux 標準の TAP/TUN デバイスを作成し、仮想 MAC コントローラとの間で Ethernet フレームを直接送受信。

## 3. ここから先は大風呂敷：F-BBが目指す「妄想」の地平

> [!CAUTION] ここから先は大風呂敷を広げています。話半分で読んでください。F-BB の「FWも回路もPC上の軽量プロセス」という極限の自由度を前提とした、将来の規格外の構想・妄想テーマです。

### 妄想 1: 知能を持つ仮想テストベンチ (System 1 意思決定モデル Jev / Kev 統合)
* **概要**:
  従来の波形目視や静的なアサーション（ルール記述）を超え、超軽量・低遅延な意思決定特化型 AI（Kev など）をシミュレーションループ内部に常駐させる構想。
* **獲得する未来**:
  * 回路の異常遷移、モータの脱調、プロトコルのセマンティックな不整合を AI が数ミリ秒で嗅ぎ分け、自律的に安全停止や警告を発行。
  * AMR 自律走行テストの「経路の滑らかさ」や「壁際走行の危険度」を AI がリアルタイム採点し、定性的な挙動評価を CI/CD 内で自動化。

### 妄想 2: 超並列 100ノード仮想クラスタ (群ロボット・車載メッシュのPC内シミュレーション)
* **概要**:
  物理ボードであれば数千万円の予算と体育館規模のスペースが必要となる「100台の搬送ロボット（AMR）」や「複数ECUが連動する車載ネットワーク」。
* **獲得する未来**:
  * F-BB では回路もファームウェアも単なる PC 上の軽量プロセスであるため、ノートPC 1台の中で 100 ノードの仮想 Zynq / 仮想 FPGA を同時に起動。
  * 仮想 SocketCAN や仮想イーサネットでメッシュネットワークを構築し、フリート制御や群制御アルゴリズムの極限負荷テストを机上だけで完結。

### 妄想 3: サイバーフィジカル・デジタルツイン (3D 物理空間との完全ループ)
* **概要**:
  F-BB の Web ダッシュボードが、WebAssembly や Three.js、外部の 3D 物理エンジン（Gazebo 等）と直結する構想。
* **獲得する未来**:
  * 画面内の 3D 空間でロボットや車両が走行し、その車輪エンコーダパルスや仮想カメラ（V4L2）の物理映像が、PC 内の仮想 FPGA の AXI バスへリアルタイムに逆流。
  * 回路の PWM 制御から物理現象、ソフトウェアの認識・制御ループまで、一切の実機基板なしで完全に閉じたサイバーフィジカル空間を提供。

### 妄想 4: AI 自律回路ファウンドリ (スペックから完全パス回路までの全自動ループ)
* **概要**:
  人間が DTS（レジスタ仕様）とテストシナリオを提示するだけで、コーディングエージェントが自律的に回路とドライバを完成させる「完全自律開発ループ」。
* **獲得する未来**:
  * エージェントが Verilog コードを生成し、F-BB の C++ シミュレーションを数秒で回し、波形（VCD）やログを自己診断。
  * バグがあれば自律的に修正を繰り返し、100% テストをパスする RTL、Linux ドライバ、ドキュメントのセットを全自動納品する。

### 妄想 5: アーキテクチャフリーな「仮想スーパー・マザーボード」
* **概要**:
  単一の物理ベンダーやアーキテクチャの枠を超え、あらゆるプロセッサとアクセラレータが同一バス上で協調する「理想の実験場」。
* **獲得する未来**:
  * ARM（Zynq）と RISC-V（PolarFire SoC）、自作カスタム TPU、レトロプロセッサ（Z80）が、単一の仮想 AXI/NoC バス上に自由に同居。
  * 地球上のどの半導体ベンダーもまだ製造していない「夢の次世代ヘテロジニアス SoC」の先行開発・アーキテクチャ評価を、PC 1台で実現。
